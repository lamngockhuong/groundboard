How a board is made

  1. You ask

    “Why can a checkout be declined after the card was authorized?” in Claude Code or any MCP client.

  2. The assistant reads the code

    It writes a board: steps, arrows, causes and open questions, each with the file, line and exact text it rests on.

  3. groundboard checks it

    Every quote is compared with the cited lines. A claim the code does not back is marked spec only or unresolved, never shown as checked.

  4. You read and edit it

    The board is laid out and rendered as an .excalidraw scene. Select a step to see its source; when the code changes, the board says it is stale.

A map of the whole app

A screen atlas puts every screen, endpoint, table and background job on boards that link to each other. Someone new clicks the Pay button and follows it to POST /orders, the orders table it writes and the receipt job it starts, each with the line that proves it.

Share it with people who do not read code: export the atlas as a static site, or publish it as a private link. 

/groundboard:atlas web
/groundboard:screen web:checkout <figma-url>
/groundboard:api orders
/groundboard:db
/groundboard:batch
/groundboard:publish

Get started

In Claude Code

Install the plugin, then ask about any repository.

/plugin marketplace add lamngockhuong/groundboard
/plugin install groundboard@groundboard
/groundboard:board why does a refund need a restock?

On your machine

Open the boards of a repository in the viewer. Needs Node.js 24 or later.

npx groundboard serve

In the browser

Open .board.json or .excalidraw files without installing anything.

Open the editor

Your code stays yours

groundboard never calls an AI model and needs no API key: your own assistant does the reading. The local viewer contacts nothing outside your machine, and the editor on this site keeps the boards you open in your browser, with nothing uploaded.
